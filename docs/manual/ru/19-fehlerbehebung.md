# Устранение неполадок {#fehlerbehebung}

Решения частых проблем и место, где Manta записывает ошибки. Если вы сообщаете об ошибке, файл журнала очень поможет.

## Файл журнала {#protokoll}

Manta записывает ошибки и важные события в файл:

`~/Library/Logs/Manta/manta.log`

Как его найти:

1. Откройте палитру команд клавишами **⇧⌘P**.
2. Выберите **Показать файл журнала в Finder**. Finder откроет папку журналов (`~/Library/Logs/Manta`) с файлом `manta.log` — именно в Finder, даже если Manta ваш файловый менеджер по умолчанию.

Там есть каждое сообщение об ошибке, которое показывает Manta, с технической ошибкой, путем и местом (локально, сервер …). При достижении 5 МБ файл сменяется; одна более старая копия сохраняется.

> [!TIP]
> Для более подробного журнала запустите Manta из Терминала командой `MANTA_LOG=debug /Applications/Manta.app/Contents/MacOS/manta`.

> [!NOTE]
> Файл журнала может содержать имена файлов и серверов. Проверьте его, прежде чем кому-то передавать. Паролей, парольных фраз и секретных ключей в нем нет — в том числе для SFTP, FTP и S3.

У плагинов собственные журналы: **Настройки** → **Плагины** → **Показать журнал** на карточке плагина.

## Manta не открывается (Gatekeeper) {#gatekeeper}

**Проблема:** при первом запуске macOS сообщает «Программа “Manta” не открыта» или «… не удается открыть, так как Apple не может проверить ее на наличие вредоносного ПО».

**Причина:** эта копия не заверена Apple. macOS блокирует такие программы при первом запуске.

**Решение:**

1. Нажмите **Готово**.
2. Откройте **Системные настройки** → **Конфиденциальность и безопасность**.
3. Внизу нажмите **Все равно открыть** рядом с Manta и подтвердите.

До macOS 15: правый клик (или нажатие с Control) по Manta в папке **Программы** → **Открыть** → **Открыть**.

## «macOS заблокировала доступ» {#berechtigungen}

**Проблема:** папка не открывается, или Manta сообщает «macOS заблокировала доступ к «…» (операция не разрешена)».

**Причина:** вы не разрешили Manta доступ к этой папке (или случайно нажали «Не разрешать»), либо папке нужен Полный доступ к диску.

**Решение:**

1. Откройте **Системные настройки** → **Конфиденциальность и безопасность** → **Файлы и папки**.
2. Найдите **Manta** и включите нужную папку («Рабочий стол», «Документы», «Загрузки», съемные тома, сетевые тома).
3. Для папок вроде `~/Library/Mail`: **Полный доступ к диску** → включите **Manta**.
4. Завершите Manta и запустите ее снова.

Если Manta нет в списке, macOS еще не спрашивала. Откройте папку один раз в Manta, и запрос появится.

«У вас нет прав на открытие этой папки» — это другое: не хватает обычных прав доступа Unix. Обратитесь к владельцу папки или измените права доступа в Finder (**Свойства**).

## Функции, управляющие Finder или Терминалом {#automation}

**Проблема:** «Показать в Finder», «Открыть в Terminal.app» или перемещение дубликатов в Корзину не работает.

**Решение:** **Системные настройки** → **Конфиденциальность и безопасность** → **Автоматизация** → в разделе **Manta** включите **Finder** и **Терминал**.

## FTP: папки не загружаются, ошибки «TLS» {#ftp-datenkanal}

**Проблема:** вход на сервер FTPS работает, но папки остаются пустыми или загружаются бесконечно, либо Manta сообщает «сеть блокирует зашифрованные соединения данных FTP».

**Причина:** некоторые корпоративные сети и брандмауэры сбрасывают зашифрованные соединения данных FTP.

**Решение:**

1. Правый клик по избранному → **Изменить подключение…** (или **⌘K** для нового подключения).
2. Установите для **Канала данных** значение **Автоматически**.
3. Подключитесь снова.

Тогда Manta передает списки и файлы без шифрования; вход остается зашифрованным. Об этом говорит щит с предупреждением на метке места.

> [!WARNING]
> Для конфиденциальных данных это не лучшее решение. Используйте вместо этого SFTP, другую сеть или VPN и установите для канала данных значение **Обязательно**.

Другие советы по FTP:

- «Не удалось установить защищенное подключение»: сервер не поддерживает FTPS на этом порту (попробуйте **FTP**, если это допустимо в вашей сети), или его сертификату нет доверия.
- Неявный FTPS (порт 990) Manta не поддерживает.

## Контейнер без оболочки {#container-ohne-shell}

**Проблема:** контейнер открывается только для чтения, или Manta сообщает «В контейнере нет оболочки».

**Причина:** чтобы показывать и изменять файлы, Manta нужен `sh` в контейнере. В образах distroless и scratch оболочки нет.

**Решение:**

- Чтение и копирование оттуда (**F5**, перетаскивание) по-прежнему работают — через `docker cp`.
- Для изменений нужен образ с оболочкой (например, отладочный вариант образа).
- Подам Kubernetes `sh` нужен даже для чтения.
- Остановленные контейнеры тоже доступны только для чтения: запустите их, чтобы вносить изменения.

## Docker или Kubernetes не появляются {#container-fehlen}

- **«Docker не запущен»**: запустите Docker Desktop.
- **«Docker не установлен»**: установите Docker Desktop или убедитесь, что команда `docker` есть в PATH. Manta также ищет в `/opt/homebrew/bin`, `/usr/local/bin` и внутри программы Docker Desktop.
- **«kubectl не установлен»**: `brew install kubectl`.
- **«Кластер Kubernetes недоступен»**: проверьте контекст и VPN или запустите локальный кластер.

## Подключения к серверам {#server}

| Сообщение | Решение |
|---|---|
| «Ключ сервера изменился» | Ключ не совпадает с `~/.ssh/known_hosts`; Manta не подключается (возможна атака «человек посередине»). Спросите у администратора отпечаток. Если сервер действительно переустановили, удалите старую запись командой из окна (`ssh-keygen -R host`). |
| «Неизвестный сервер» | Первое подключение к этому серверу. Сравните отпечаток и нажмите **Подключиться и запомнить**, см. [Подключения](08-verbindungen.md). |
| «Сохраненный пароль не найден в Связке ключей» | Объект был удален, например в программе «Связка ключей». Введите пароль и оставьте **Запомнить пароль** включенным. |
| «В ssh-agent нет подходящего ключа» | `ssh-add ~/.ssh/id_ed25519` |
| «Часы на вашем Mac идут неправильно» | **Системные настройки** → **Основные** → **Дата и время** → устанавливать автоматически. |
| «Бакет находится в другом регионе» | Укажите в окне названный регион. |
| «Подключение к серверу потеряно» | Проверьте сеть, затем нажмите **Повторить**. |

## Передача не продвигается {#uebertragungen}

| Что вы видите | Решение |
|---|---|
| «Ожидание подключения… (попытка 5, следующая через 16 с)» | Сеть или сервер недоступны. Manta продолжает попытки и продолжит с того же места. Проверьте Wi-Fi/VPN; **Повторить сейчас** сразу запускает следующую попытку. |
| **Нет подключения к интернету** вверху окна **Передачи** | Ваш Mac не в сети. Как только он снова будет в сети, передачи продолжатся сами. |
| «Требуется подключение к …» | После перезапуска нет подключения к серверу. Нажмите **Подключиться** и введите пароль. |
| «Приостановлено · …» | Вы (или **Приостановить все**) приостановили операцию. Нажмите **Продолжить**. |
| Скрытые файлы `.NAME.manta-part` в цели | Частичные файлы прерванной операции. Не трогайте их, если операцию нужно продолжить; иначе их можно удалить. |

См. [Пауза и возобновление передач](05-dateien.md#pausieren).

## Обновление не удается {#updates}

См. [Обновления](17-updates.md#blockiert). Чаще всего Manta запущена не из папки **Программы**.

## Облако: «Удалить загрузку» не работает {#cloud}

Для Google Drive, OneDrive, Dropbox и других решает программа поставщика. Используйте Finder: правый клик → **Удалить загрузку**. См. [Облачные хранилища](09-cloud.md#download-entfernen).

## Папка показывает устаревшее содержимое {#aktualisieren}

Нажмите **⌘R**. Изменения, сделанные другими программами или на сервере, Manta видит только после обновления.

## Сброс Manta {#zuruecksetzen}

В крайнем случае:

1. Завершите Manta.
2. Переименуйте `~/Library/Application Support/Manta` (например, в `Manta old`).
3. Запустите Manta. Она запустится как в первый раз.

Ваше избранное и быстрые действия останутся в переименованной папке.
